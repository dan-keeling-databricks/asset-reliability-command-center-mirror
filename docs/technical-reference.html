Bounded read path

Fleet sparklines use eight index-backed lateral probes over (scenario_id, pump_id, event_time DESC), limited to 20 samples per pump. Raw telemetry retention runs every five minutes and deletes at most 1,000 expired rows per scenario/pump batch with short lock and statement timeouts.

Agent runtime and framework

The application does not use LangGraph, LangChain, the OpenAI Agents SDK, or another orchestration framework. It implements a custom tool-calling loop directly.

Framework classification

The runtime is best described as an application-specific, ReAct-style loop using OpenAI-compatible chat/tool messages. FastAPI hosts it; asyncio provides concurrency; direct HTTP clients call model serving and Unity Gateway.

# Conceptual structure; simplified from ProductionCommandCenterRuntime
async def run_agent(incident_id):
    identity = await wait_for_obo_identity(incident.scenario_id)
    skill = await skill_gateway.call_tool(configured_skill, {}, identity.token)
    tools = await gateway.list_tools(identity.token)
    model_tools = convert_mcp_schemas(tools)

    while True:
        turn = await model.turn(messages, tools=model_tools)
        if not turn.tool_calls:
            resolve_or_continue(turn)
            return

        for call in turn.tool_calls:
            try:
                result = await gateway.call_tool(call.name, call.args, identity.token)
            except GatewayAsk as ask:
                await persist_waiting_state(ask.serialized_request, ask.approval_url)
                return

            messages.append(tool_result(result))
            apply_application_specific_branches(call.name, result)

06

MCP service and tool surface

The agent is configured with one Unity Gateway MCP service URL. It does not discover MCP servers. It discovers the tools exposed by that service for the current request context.

Permission and exposure model

The operator’s OBO token determines whether the configured MCP service can be accessed. The MCP service’s include_tool_selectors determines which source tools are advertised. The custom service policy determines whether an advertised call is allowed to execute.

ToolInputsReads / writesPolicy result
get_asset_telemetryasset_idReads current snapshot; returns vibration, warning threshold, flow, current, trend, timestamp.ALLOW
assess_failure_riskasset_id, optional maintenance_window_daysReads up to 12 recent samples; returns probability, risk band, persistence and correlated evidence.ALLOW
prepare_work_orderasset_id, action, incident_idReturns non-binding part, availability, duration, and planned window. No work order is written.ALLOW
submit_work_orderasset_id, action, incident_id, planned_windowAfter authorization, idempotently inserts a scheduled work order into Lakebase.ASK → ALLOW

The returned MCP schemas are converted into the model API’s function-tool representation. Before any call, the runtime also verifies that the model-selected name is present in the returned available map.

07

Governed Skill loading

Skill loading is dynamic in content but not dynamic in selection.

QuestionCurrent behavior
Does the runtime always load a Skill?Yes. Missing Skill Gateway configuration fails the production run.
Who selects the Skill?Deployment configuration. GOVERNED_SKILL_TOOL identifies one Skill tool.
Does the agent search for relevant Skills?No. There is no Skill enumeration, retrieval, ranking, or model selection step.
Is the Skill content embedded in application code?No. The current content is fetched through the Skill Gateway for each incident and inserted into the system prompt.
Whose identity is used?The selected operator’s OBO token. Required UC privileges are USE_CATALOG, USE_SCHEMA, and Skill READ_VOLUME.
if not skill_gateway or not settings.governed_skill_tool:
    raise RuntimeError("Governed Skill Gateway configuration is missing")

skill_response = await skill_gateway.call_tool(
    settings.governed_skill_tool,
    {},
    identity.token,
)
skill_instructions = structured(skill_response)["result"]

The loop therefore implements “load this configured governed Skill,” not “find a Skill appropriate to this alert.” The UI does not predict the Skill name; it renders the actual Skill event after the load succeeds.

Policy contract

CASE
  WHEN event:type::string = 'request'
   AND event:context.tool.name::string = 'submit_work_order'
  THEN {
    "result": "ASK",
    "reason": "Submitting a maintenance work order requires human authorization."
  }
  ELSE { "result": "ALLOW", "reason": "" }
END
  • ASK is decoded from Gateway error code -32042 and its URL elicitation.
  • The exact serialized JSON-RPC request is stored with the pending approval.
  • The runtime returns immediately. It does not execute the source tool or produce a successful terminal conclusion.
  • After external authorization, the application’s approval endpoint replays the exact stored bytes through Gateway.
  • A repeated ASK leaves the incident waiting. Errors and denials are recorded as failures, not successful actions.

OBO safety requirement for static or dynamic tools

Tool schemas may be static, cached, or discovered without changing OBO semantics. The tool execution wrapper must resolve the token from the current incident context. A singleton tool object must never capture one user’s token, because independent incidents and users can execute concurrently.

# Correct: schema/wrapper is reusable; identity is resolved per invocation
async def call_governed_tool(name, arguments, incident_context):
    identity = identity_registry.get(incident_context.scenario_id)
    return await gateway.call_tool(name, arguments, identity.token)

11

Concurrency, idempotency, and failure behavior

Concurrent incident evaluation
Every incident runs in a separate asyncio task. P-202 and P-207 can therefore be evaluated concurrently. The model client and Gateway client are shared, while message history, incident state, and OBO lookup are scoped per run.
Duplicate suppression
Database uniqueness constraints suppress duplicate active scenarios, commands, incidents, telemetry events, and work orders. The evaluator’s transaction is the authority for incident creation.
Pending approval recovery
The serialized request and approval metadata survive in Lakebase, but the bearer token does not. After an App restart, a live operator request must repopulate process-local identity before replay can succeed.
Producer or Kafka failure
Kafka acknowledgement precedes heartbeat advancement. A broker failure makes the producer job fail visibly and restart. Sequence recovery prevents event-ID reuse.
SSE disconnect
The browser reconnects using a revision cursor. The App rebuilds state from Lakebase; notifications and SSE messages are not treated as durable records.
Model formatting error
The runtime attempts one correction for tool-call rationale and terminal response shape. If rationale formatting remains invalid, it emits a deterministic prospective fallback. Successful governed writes also receive a fallback conclusion if the post-approval model call fails.
